Skill development as the main thread

The centre of gravity was a family of OpenCode skills. meld-deepresearch went from a single research skill to a small cooperating family, releasing v0.1.0, v0.2.0, v0.3.0 and v0.4.0 in quick succession. v0.2.0 turned the handling of paywalled and bot-walled sources into an explicit rule, logging blocked pages as observations with HTTP status and labelling thinly supported claims unknown; the validator now also returns fix hints. v0.3.0 split the work into three cooperating skills (core research, spreadsheet analysis, and a third capability skill) with hard delivery gates. v0.4.0 added a thin meld.py wrapper around the six gate scripts and downgraded some gates, making re-runs safer. Alongside this came a bilingual GitHub Pages landing page with light and dark themes, English and Chinese READMEs, and M1–M3 milestone scripts and CI.

sopen-translate was started from scratch: MV3 skeleton, a providers protocol layer with presets, model lists and a glossary pipeline, bilingual page rendering with chunk splitting, a circuit breaker and progress reporting, plus smoke tests, a page-state reset fix and JSDoc-based checkJs type checking. Selection translation was dropped in favour of page translation only.

opencode-skill-management shipped a skill_management plugin with list, inspect, disable and enable actions that work purely by writing permission rules into the global config rather than touching skill files; it was released as rc.0, rc.1, v0.2.0 and finally v1.0.0, with the rc.1 run used to validate CI trusted publishing over OIDC. opencode-go-model-picker released v1.1.0, v1.3.0 and v1.4.0, restructuring the output into a three-part body plus data appendix and adding discover-agents.mjs and snapshot-summary.mjs; the later release added an agent-discovery inventory, mode/hidden/traits fields, skippedBuiltins reporting, BOM-tolerant atomic JSON helpers and proxy re-execution for the network scripts. asset-inventory released v1.14.0, v1.15.0 and the patches v1.15.1 through v1.15.3: one-line install via skills.sh, a workflow-first SKILL.md, a registry-first host-command scan with an id completeness guard, and a move of mode routing and table rules into references.

Agent, sandbox and knowledge work

opencode-agent-sandbox was created and grown into a documentation base: AGENTS.md, a knowledge/ directory for Git, GitHub and OpenCode findings (V2 distribution, architecture, auth, Windows path pitfalls), plus corrections to outdated conclusions about subcommand lists, bundled skill counts, Windows ports and remote branch deletion. The profile repository sogeisetsu/sogeisetsu received most of its work in automation: a 30-day activity card, a daily report moving to rolling two-hourly updates with a manual date input, English copy throughout, a peak/average chart summary, statistics that can no longer disagree with their breakdown, checkout/setup-node upgrades to v7, and .gitattributes enforcing LF.
