    sogeisetsu/opencode-skill-management

    What this is

    skill_management puts a control panel on the skills installed in your OpenCode setup. It can list them, explain why one is unavailable, hide one from the model, and bring it back.

    Disabling never touches skill files: it writes a single skill permission rule into your global config (effect: "deny", or "ask" for a soft disable). Nothing is deleted, moved or rewritten, and removing the rule restores the skill exactly as it was.

    ActionWhat it doesWrites config
    listEvery registered skill with its effective state for the calling agent (available / disabled / ask)no
    inspectWhy one skill is (un)available: the matching rule, per-agent differences, how its id was derivedno
    disableHide it from the model and reject loading it (effect: "ask" keeps it listed and asks on load)yes
    enableRemove the blocking rule again, whoever wrote ityes

    Install in one command: opencode plugin add github:sogeisetsu/opencode-skill-management (details below).

    What's changed since v0.1.0

    Fixed — list reported the wrong state. It merged every agent's permission rules before evaluating them, so deny rules owned by sub-agents (explorer, title, …) leaked into the caller's result: on a stock setup 28 of 29 skills showed up as disabled while inspect said they were available.
