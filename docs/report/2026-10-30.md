  > # v1.1.0
  > 
  > \`skill\_management\` gives every installed OpenCode skill a switch: list what is installed, find out
  > why one will not load, hide it from the model, and put it back. Disabling writes \*\*one\*\* global
  > \`skill\` permission rule — no skill file is ever moved, edited or deleted.

  > ## Breaking change in 1.1.0
  > 
  > All four actions now return \*\*one JSON object\*\* instead of Markdown. The tool also declares an
  > \`output\` JSON Schema, so the host validates every result; this is a real structured tool result,
  > not Markdown wrapped in a JSON string.
  > 
  > - Envelope: \`schemaVersion\` (currently \`1\`), \`action\`, \`ok\`, \`warnings\`.
  > - Failures use \`ok: false\` plus \`error: { code, message }\`; success is no longer inferred from
  > ✅ / ❌ in the text.
  > - \`list\` returns \`callerAgent\`, \`summary\`, \`skills\[\]\`, \`config\`, \`sidecar\`, \`consistency\`.
  > \`description\` is still the first line, no longer truncated to 60 characters.
  > - \`inspect\` returns \`skill\`, \`idDerivation\`, \`agents\[\]\`, \`caller\`, \`conclusion\`. Missing and
  > ambiguous targets use \`skill\_not\_found\` / \`name\_ambiguous\`.
  > - \`disable\` / \`enable\` return \`changed\`, \`reason\`, \`before\`, \`diff\`, \`verification\`, \`backup\`,
  > \`sidecar\`; \`enable\` also returns \`location\`, \`rule\`, \`candidates\`, \`relatedRules\`.
  > - \`enable\` now returns \`ok: false\` with \`config\_unparsable\` when the target config cannot be
  > parsed and no candidate rule exists, instead of claiming "nothing to change".
  > 
  > Nothing else broke: actions, input fields, the written rule shape, the same-line marker format
  > and the single-file layout are unchanged.

  > ## What it does
  > 
  > | Action | What you get | Writes config |
  > |---|---|---|
  > | \`list\` | Every registered skill and its effective state for the \*\*calling agent\*\* (\`available\` / \`disabled\` / \`ask\`) | No |
  > | \`inspect\` | Why one skill is (not) usable: the matched rule, per-agent differences, how the id was derived | No |
  > | \`disable\` | Hidden from the model-visible list and rejected at load (\`effect: "ask"\` keeps it listed with confirmation) | Yes |
  > | \`enable\` | Deletes the one blocking rule, whoever wrote it | Yes |
  > 
  > Permissions are evaluated for the \*\*calling agent only\*\*: last match wins (\`findLast\`, with \`\*\`
  > and \`?\` globs), and \*\*no match falls back to \`ask\`, not \`allow\`\*\*.
  > 
  > The rule \`disable\` writes is exactly this line (the trailing comment is the provenance marker
  > \`enable\` uses):
  > 
  > \`\`\`jsonc
  > { "action": "skill", "resource": "windows-shell", "effect": "deny" } // skill\_management
  > \`\`\`
  > 
  > Writes are atomic, preserve indentation, key order, line endings (CRLF/LF) and BOM, keep one
  > backup, and are verified by reloading the host and polling the caller's rule set; a write the
  > host did not pick up is rolled back.
  > 
  > ## Usage
