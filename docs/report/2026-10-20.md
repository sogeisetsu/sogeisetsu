  > ## What this is
  > 
  > \`skill\_management\` puts a control panel on the skills installed in your OpenCode setup. It can list them, explain why one is unavailable, hide one from the model, and bring it back.
  > 
  > Disabling never touches skill files: it writes a single \`skill\` permission rule into your global config (\`effect: "deny"\`, or \`"ask"\` for a soft disable). Nothing is deleted, moved or rewritten, and removing the rule restores the skill exactly as it was.
  > 
  > | Action | What it does | Writes config |
  > |---|---|---|
  > | \`list\` | Every registered skill with its effective state for the calling agent (\`available\` / \`disabled\` / \`ask\`) | no |
  > | \`inspect\` | Why one skill is (un)available: the matching rule, per-agent differences, how its id was derived | no |
  > | \`disable\` | Hide it from the model and reject loading it (\`effect: "ask"\` keeps it listed and asks on load) | yes |
  > | \`enable\` | Remove the blocking rule again, whoever wrote it | yes |
  > 
  > Install in one command: \`opencode plugin add github:sogeisetsu/opencode-skill-management\` (details below).
  >
